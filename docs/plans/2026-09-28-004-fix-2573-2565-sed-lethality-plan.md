## Cause établie à la source (sonde, worktree git réel)

| commande | prédicat terminal AVANT | note |
|---|---|---|
| Case A (verbatim) | `is_tier3_dangerous_for_lethality` via **`\beval\s`** | **PAS le sed.** `eval` = nom de la cible de test `cargo test --test eval`, pas le builtin. Le `sed -n '…p'` seul mesure `False`. |
| Case B (verbatim) | `is_tier3_dangerous_for_lethality` via **`\bsed\s+(-\w*i\|-i\w*)\b`** | `sed -i` sur fichier relatif in-worktree. `_destination_veto_reason` = None (sed -i n'est pas un write-kind). |

**Correction de diagnostic** : la sonde préalable attribuait case A au sed (« flags the sed without honoring `_is_safe_sed_print_only` ») ; la mesure verbatim montre que le tueur est `\beval\s` sur `--test eval`, dans le segment `cargo`, pas le sed. Le carve print-only sed (fix A demandé) est réel et correct (il traite `… | sed -n '/rm -rf/p'`) mais **ne rend PAS survivable le case A verbatim** — il faut le narrowing `eval`.

## Le fix (létalité seule)

1. **Print-only sed (fix A demandé, `tier1.py`)** — `_blank_print_only_sed_segments` : chaque segment `_is_safe_sed_print_only` (réutilisé verbatim) est retiré avant le scan des verbes dans `is_tier3_dangerous_for_lethality`. Miroir cpp#213 (drop-segment-puis-recheck). Effet : un filtre de lecture dont le SCRIPT contient une chaîne dangereuse (`sed -n '/rm -rf/p'`) n'est plus fatal. **N'affecte pas** le case A verbatim (l'`eval` est hors du sed).
2. **In-worktree `sed -i` (fix B, `tier1.py` + `permissions.py`)** — `sed_i_confined_to_worktree` (miroir `rm_confined_to_pilot_scratch`) : retire chaque segment `sed -i` **substitution** (`_SED_I_SAFE_SUBST_SCRIPT_RE`, sans `w`/`W`/`e`, sans `-e`/`-f`) dont TOUTE cible est relative et sous le worktree (`is_within_project`, symlink-aware), puis recheck le reste. Câblé dans `_denial_is_terminal` avec `not rm_confined_… and not sed_i_confined_…`. Effet : **case B survivable**. Placé au niveau cwd-aware, donc `is_tier3_dangerous_for_lethality("sed -i … realfile.rs") = True` (cpp#203) est inchangé.
3. **`eval` command-position (fix réel du case A) — BLOQUÉ.** Swap de la seule entrée `\beval\s` du tuple létalité `_TIER3_VERB_PATTERNS_FOR_LETHALITY` par `(?:^|[|&;\n(])\s*eval\s` (proven-danger seulement en position commande ; `--test eval`/`--eval` deviennent survivables ; `eval "$(x)"`, `x | eval y`, `foo && eval x` restent terminaux). Admission (`TIER3_PATTERNS`) byte-identique. **Édition refusée par le classifieur auto-mode (« Security Weaken »)** ; conformément au protocole, pas de contournement — patch exact remis pour apply humain-validé.
